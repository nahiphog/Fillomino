# Solver benchmark

This report is generated by `node benchmarks/report.mjs` from [results.json](results.json). Run `npm run benchmark` to reproduce the measurements on your machine.

## Method

- Baseline: deployed solver at commit b3dcd55016af39d42653d5313d015068e224200a, preserved with only an import-path change and optional counters.
- 25 fixed puzzles, each measured in solve and count-up-to-two modes, 3 repetitions per engine. Engine order alternates by repetition. Small warm-ups precede measurement.
- Same 1000ms deadline for both engines. No tests/builds run concurrently with the recorded benchmark. Wall-clock results may still vary with host load and garbage collection.
- Deterministic square/rectangular generated fixtures at different clue densities, the user example, an empty grid, a contradiction, a single 225 clue, and six unique fixtures independently verified by the previous solver. Exact clue arrays are included in the JSON.
- Environment: v24.19.0, win32, Intel(R) Core(TM) i7-8665U CPU @ 1.90GHz.
- Returned solutions are independently validated and checked against clues. Counts must agree whenever both searches finish. A timeout is inconclusive, even with one solution found.

## Interpretation and implementation

The new engine runs completed-region, forced-merge, reachable-area, exact-fit, bottleneck, and singleton deductions before guessing. A work queue tracks affected values; a deletion trail restores domains after failed guesses. Search chooses the cell with the fewest candidates, with a neighboring-constraint tie-break. A region-search attempt is retained for broad sparse cases after propagation: up to 50ms normally, 200ms with at most 25% original clues, always capped at one third of the remaining budget. If that attempt times out, its solution counts are discarded and cell search starts independently.

Branches are different units: the reference counts whole-region placements, while the improved total includes cell assignments and any region placements from the bounded attempt. The raw data separately records region branches, region shapes, propagation checks, forced assignments, and deduction removals. Lower branch counts alone do not prove faster runtime.

These fixtures are a reproducible regression corpus, not a representative survey of all published Fillomino puzzles. The engine was tuned using this corpus; results are in-sample. It still uses backtracking and may time out on hard sparse grids. No uniqueness assumption is used for deductions. The independent 3×3 oracle, larger cross-checks, and undo/timeout regression tests are correctness checks, not a mathematical proof of the implementation.
